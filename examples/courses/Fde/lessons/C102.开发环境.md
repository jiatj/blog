## 本次目标

不是「装过」，而是能亲手运行：

- 找到自己的项目目录。
- 检测 Node.js、npm 与 Git。
- 运行一个脚本，看到真实输出。
- 自己停止并重新启动项目。

> 环境通过之后，再进入功能修改。不要求记忆所有命令，也不要求一次装齐所有后续工具。

## 准备

### 四个工具

| 工具 | 当前用途 |
| --- | --- |
| WorkBuddy | 辅助检查环境、解释操作 |
| Node.js 与 npm | 运行课程代码与项目脚本 |
| VS Code | 打开文件、终端与操作记录 |
| Git | 记录与比较版本，本次先完成安装检测 |

另需一个常用浏览器。所有工具从官方渠道获取：WorkBuddy（www.workbuddy.cn）、Node.js（nodejs.org）、VS Code（code.visualstudio.com）、Git（git-scm.com）。已安装且版本可用时，继续使用现有安装即可；已有能稳定使用的同类 AI 或编辑器工具，也可以完成相同任务。

安装与登录在你自己的设备上完成——环境是你自己的，最终验收看的也是你电脑上的真实输出。

## A 基础：三个窗口，对准同一个项目

1. 用 VS Code 打开个人练习目录。
2. 在 WorkBuddy 选择或授权相同目录。
3. 打开终端，检查当前路径。

编辑器、AI 工具、终端指向同一个目录，后面的操作才不会「改了文件却找不到」。优先使用自己有权限、路径稳定的目录；不要把桌面所有文件交给 AI 批量修改。

## A 基础：让 AI 做一次检测

给 WorkBuddy 一个明确任务：

~~~text
先检查，再决定是否需要安装。
报告实际命令、输出与未通过项。
不要把「准备执行」写成「已经完成」。
~~~

> 返回后：自己在终端重复一遍检测命令。安装未成功时，记录准确的报错信息，不要反复发送「再试一次」。

## A 基础：安装 Git

1. 在终端执行 `git --version`，先判断是否已安装。
2. 未安装：从 git-scm.com 下载安装包。Windows 安装时保持默认选项即可，重点确认 PATH 相关选项被勾选；macOS 可用官方安装包或 Homebrew。
3. 安装后保存关闭 VS Code，重新打开，新建一个终端再验证一次。

~~~powershell
git --version
~~~

> 预期：输出 `git version` 和版本号。记录下这个输出。

注意：`not a git repository` 不是安装失败——它说明 Git 已经能运行，只是当前目录还不是一个仓库，不要在这里随意初始化。本次也不需要 GitHub 账号或远程认证；提交、恢复与分支等版本操作，会在课程后续阶段学习。

## A 基础：用运行证明环境可用

先创建文件 `check.cjs`，内容如下：

~~~javascript
const note = { title: "我的第一条笔记" };
console.log(note.title);
console.log("Node.js 可以运行课程代码");
~~~

保存后在终端执行：

~~~powershell
node --version
npm.cmd --version
node .\check.cjs
~~~

> 预期：前两条返回版本号，最后一条输出两行文字。这三条是检测和运行命令，不是安装命令。

只显示版本还不够——把文件保存并运行成功才算数。试着把标题改成你自己的一句话，再运行一次，看输出是否同步变化。

## A 基础：启动笔记本骨架

从脚本，走向课程项目：

- 打开课程发放的笔记本项目。
- 按 README 核对依赖、版本与实际脚本。
- 启动项目，浏览器按终端提示的地址打开，观察当前页面。
- 自己完成一次停止与重启。

> 还没有拿到项目骨架时，以 check.cjs 的成功运行作为本阶段交付，项目启动一项保持「未验证」。已经拿到骨架的同学，可以继续检查新建、保存、刷新是否正常。

## B 提高 / C 高级

进度快的同学，继续验证一层：

- **B 提高：** 运行 npm 脚本示例；启动一个本地文本服务，修改响应内容再运行。
- **C 高级：** 比较两台电脑的环境诊断记录，能解释区别，再进入下一项。

> 记录里只写版本、路径、脚本等信息，不要复制密钥内容。

## 遇到阻塞：先定位，再请求帮助

~~~text
我在哪个目录：……
我执行的命令：……
第一条错误：……
我预期看到：……
我已检查：……
~~~

把真实信息填进去，不只截一张看不清的屏幕。常见排查入口：

- 找不到命令 → 检查安装或 PATH。
- 找不到文件 → 检查当前目录。
- 缺脚本 → 检查 package.json。
- 端口冲突 → 检查现有进程或换端口。

## 如何提交作业

必须一步步记录并完成：

1. 登录 gitee（gitee.com），创建仓库，名称是 `fde-01`，选择**开源**，不是私有。
2. 分支模型选择单分支（master）。
3. 本地创建文件夹 `fde-01`，在下面创建目录 `lesson-01` 到 `lesson-16`，每个目录下创建一个 README.md 文件，然后初始化并推送：

~~~powershell
cd fde-01
git add .
git commit -m "初始化作业仓库"
git push
~~~

每天课程的作业就在对应 `lesson-x` 目录下的 README.md 中完成，格式是 Markdown。
