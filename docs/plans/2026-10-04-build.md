# 造物栏目实施计划

**目标：**公开展示作品、路线图、造物日志和产出文件，中英文界面分别使用对应语言。

**架构：**沿用 Next.js App Router 与文件内容。每个作品一个 `artifact.json`，草稿过滤、步骤关联、进度计算和直播选择由独立模块处理；没有后台或自动 AI 发布。

**技术：**现有 Next.js、React、TypeScript、CSS Modules、Node.js 文件接口；不新增依赖。

1. 新增 `lib/build/{types,model,read}.ts`、`scripts/build.mjs`：校验数据、过滤草稿、计算进度、读取作品和已公开文件。
2. 新增 `app/[locale]/build/` 列表、作品详情、日志详情和 `app/build-assets/` 下载接口；共用 `components/build/`，以纵向章节和步骤列表组织内容。直播到期重新读取，时间为北京时间。
3. 修改 `lib/site-config.ts`、`lib/dictionary.ts`、`components/site-shell.tsx`、`app/sitemap.ts`：导航为首页、造物、课程、发现、文章；项目和关于移至页脚，旧路由保留。
4. 新增 `examples/build/` 明确标注的中英文示例，默认不发布。新增 `doc/build.md`，更新 README、`doc/content-model.md`、环境变量、package.json 命令和发布脚本。首页文案同步翻译。
5. 使用 `node --test scripts/test-build.mjs` 覆盖断链、草稿、进度变化、直播到期、文件访问和读取更新；执行类型检查、构建及生产 HTTP/浏览器验收。

验收重点：不泄露草稿、稳定步骤 ID、取消步骤保留历史但不计入进度、直播到期自动切换、不存在文件返回 404、修改内容后无需重新构建。示例的状态和时间不是实际业务承诺。
